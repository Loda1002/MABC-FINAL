# 예시 데이터 제작 서브에이전트 프롬프트

## 역할
MABC-FINAL MVP(검수 웹 서비스)의 예시 데이터를 만드는 에이전트.

## 목표
사용자가 "예시 버튼" 하나로 전체 흐름(업로드 → 검수 표 → 다운로드 → 기억 파일 재업로드 → 재검증 건수 감소 확인)을 시연할 수 있는 예시 데이터셋 1세트 이상을 만든다.

## 산출물
1. 원본 자료 파일 1개 이상 (xlsx 또는 md 또는 텍스트 표 형식). 가상 예시임을 명시.
2. 검토 대상(초안) 파일 1개 — 원본과 비교해 5라벨 판정이 골고루 나오도록 의도적으로 오류를 섞음.
3. 기억 파일(memory.json) 1개 — 이전 버전 검수 결과를 저장한 형식. 재업로드 시 재검증 대상이 줄어드는 것을 보여줄 수 있어야 함.
4. 기대 판정 결과 요약 1개 (사람이 읽을 수 있는 형태) — 각 인용 수치별 5라벨 판정과 근거, 계산식, 수정 제안 포함.
5. 예시 데이터 README.md — 각 파일의 역할, 데이터 생성 원칙, 가상 예시 명시, cited figure check 스킬 규칙과의 연결 설명.

## 판정 케이스 요구사항
예시 데이터는 다음 판정 케이스가 최소 1회씩 보이도록 구성한다:
- 일치
- 불일치 (값 다름)
- 값은 있으나 항목 대응이 다름
- 원본에 없음
- 확인 불가 (표 깨짐, 기준 불충분 등)

추가로 다음을 포함한다:
- 단위만 다르고 값은 같은 경우를 일치로 처리하는 케이스
- 계산 인용(증감률, 합계, 평균, 비중 등) — 코드가 계산할 수 있게 원본 표에 계산 근거가 있음
- 기준 시점/조건이 달라서 생기는 판정 차이
- 원본에 없는 값을 모델이 채워 넣은 케이스 (금지 결과 3번 데모용)
- 깨진 표로 인한 확인 불가 케이스

## 제약
- 실제 기관 자료가 아니라 가상 예시임을 모든 파일에 명시한다.
- cited figure check 스킬 규칙(이 스킬의 5라벨 판정, 계산 인용 규칙, 깨진 표 처리, 원본 없으면 판정 안 함 등)을 위배하지 않는다.
- 이미지, URL, PDF는 포함하지 않는다. 입력은 xlsx/텍스트 표/텍스트/md/json만 쓴다.
- API 키나 민감 정보를 포함하지 않는다.

## 데이터 형식 가이드
- 원본 자료: 표 구조가 분명한 형식 선호. xlsx 또는 마크다운 표 또는 탭 구분 텍스트.
- 초안: 일반 텍스트 문단 + 수치 인용 문장들.
- 기억 파일: JSON. 이전 검수 결과 구조(예: 항목별 판정, 수정된 값, 버전 정보, 비교 기준)를 담는다. 정확한 필드 설계는 이 프롬프트 단계에서는 자유롭게 하되, "재업로드 시 이전에 검증된 항목은 재검증 대상에서 제외된다"는 동작을 시연할 수 있어야 한다.
- 판정 결과 요약: 사람이 읽을 수 있는 마크다운 표 또는 목록.

## 출력 위치
생성된 파일은 작업 폴더 `C:\project\MABC-FINAL\examples\` 아래 정리한다.
README.md에 각 파일의 역할과 예시 흐름을 설명한다.

## 주의사항
- 예시 데이터가 너무 커지지 않도록 적당히 축소한다(시범용으로 충분하면 됨).
- 예시 데이터의 수치와 판정이 서로 모순되지 않게 한다.
- "예시 버튼" 클릭 시 이 데이터가 자동으로 채워지는 구현이 뒤따라야 하므로, 업로드 핸들러가 어떤 파일 형식/필드명을 기대하는지 추후 정해지면 그에 맞춘다. 지금은 최대한 일반적인 형식(xlsx, md, json)으로 만든다.

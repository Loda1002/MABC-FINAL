# MABC-FINAL MVP 설계 문서

생성: 2026-09-13
용도: MABC2026 결선 MVP(검수 웹 서비스)의 구조·엔드포인트·데이터 흐름 정의
컨텍스트 부착: agent loop에서 항상 함께 읽는 3개 문서 중 하나

---

## 1. 목적

AI가 원본 자료를 보고 쓴 문서(초안)의 수치·주장을 원본 자료와 대조해 검수하고, 버전이 올라가면 이전 검수 상태(기억 파일)를 이용해 뭐가 바뀌었는지, 뭐가 잘못됐는지 확인하는 웹 서비스를 제공한다.

핵심 사용자 시나리오:
1. 원본 자료와 초안을 업로드한다.
2. 검수 표를 확인한다 (판정, 잘못된 부분, 근거, 수정 제안, 확인 여부).
3. before/after 시각화에서 수정 내용을 확인한다.
4. 고쳐진 파일과 기억 파일을 다운로드한다.
5. 기억 파일을 다시 올리면 재검증 대상이 줄어든 것을 확인한다.
6. 예시 버튼 하나로 전체 흐름을 시연한다.

- 타 LLM API 호출
- 유료 외부 API
- DB 사용
- 로그인·인증
- cited figure check를 우회하고 코드가 직접 판정하는 것

## 3. 시스템 구조

### 3.1 아키텍처 개요

```
브라우저 (프론트엔드)
  │
  ▼ HTTP (HTTPS)
서버 (백엔드, FastAPI 기반)
  │
  ├── /api/upload        — 파일 업로드 (원본, 초안)
  ├── /api/check         — cited figure check 스킬 호출 + 결과 조립
  ├── /api/download      — 고쳐진 파일, 기억 파일 다운로드
  ├── /api/rerun         — 기억 파일 재업로드 → 재검증 대상 감소
  ├── /api/example       — 예시 데이터 채워넣기
  └── /api/status        — 진행 상황 스트리밍/폴링
```

### 3.2 구성 요소

| 구성 요소 | 역할 | 비고 |
|-----------|------|------|
| 프론트엔드 | 업로드 2칸, 결과 표, before/after 시각화, 다운로드, 예시 버튼, 진행 문구, 고지문 | 정적 파일 + JS |
| 백엔드 API | 파일 수신·파싱, Solar Pro 4 호출, cited figure check 스킬 호출, 결과 조립, 다운로드 응답 | FastAPI |
| cited figure check 스킬 | 원본-초안 대조, 5라벨 판정, 계산 인용 검증 | 호출부 무결성 필수 |
| Solar Pro 4 API | 스킬 실행 주체 | 서버 사이드에서만 호출, 키로 클라이언트 노출 금지 |
| 기억 파일 (memory.json) | 이전 버전 검수 결과 저장, 재검증 시 대상 축소에 사용 | 다운로드·업로드 대상 |

### 3.3 데이터 흐름

1. **업로드**: 사용자가 원본 파일과 초안 파일을 업로드 → 서버가 임시 저장
2. **검수 요청**: `/api/check` 호출 → 백엔드가 원본·초안을 파싱하여 cited figure check 스킬에 전달 → Solar Pro 4가 스킬을 실행하여 5라벨 판정 결과 반환
3. **결과 조립**: 백엔드가 스킬 결과를 검수 표 형태로 조립, 계산 인용은 코드가 직접 계산·비교, 수정 제안 포함
4. **before/after 생성**: 초안 텍스트에서 수정된 부분을 표시 (빨강=before 문제 부분, 파랑=after 수정 후)
5. **다운로드**: 고쳐진 파일(초안에서 오류 수정된 버전)과 기억 파일(검수 결과 JSON) 제공
6. **재검증**: 기억 파일을 다시 업로드 → 이전 검수에서 이미 확인된 항목은 재검증 대상에서 제외 → 재검증 건수 감소 표시

## 4. 엔드포인트 설계

### 4.1 POST /api/upload

- 용도: 원본 파일 + 초안 파일 업로드
- 요청: multipart/form-data, 필드: `original` (파일), `draft` (파일)
- 응답: `{ "status": "uploaded", "original_id": "...", "draft_id": "..." }`
- 검증: 입력 파일은 xlsx, 텍스트 표, 텍스트, md, json만 허용. 이미지/URL/PDF 거부.

### 4.2 POST /api/check

- 용도: 업로드된 원본·초안으로 cited figure check 스킬 실행
- 요청: `{ "original_id": "...", "draft_id": "..." }`
- 응답: `{ "status": "processing" | "done", "results": [...], "elapsed_seconds": N }`
- 결과 항목 (검수용 표):
  - 인용된 항목/수치
  - 원본 자료에서 확인한 대응 값
  - 판정: 5라벨 중 하나 (일치 / 불일치 / 값은 있으나 항목 대응이 다름 / 원본에 없음 / 확인 불가)
  - 근거: 원본 표의 해당 행/열 라벨, 단위, 기준 시점 등
  - 수정 제안
  - 확인 여부 (체크박스 상태)
- 진행 문구: "에이전트가 원본과 초안을 대조 중입니다" 등 표시
- 고지문: "LLM 활용 서비스이므로 사용자 검수가 필요하며, 실수가 있을 수 있습니다" 포함

### 4.3 GET /api/download/{type}

- 용도: 고쳐진 파일 또는 기억 파일 다운로드
- type: `fixed` (고쳐진 초안), `memory` (기억 파일 json)
- 응답: 파일 스트림 + Content-Disposition 헤더

### 4.4 POST /api/rerun

- 용도: 기억 파일 재업로드 → 재검증 대상 축소
- 요청: `{ "memory_file": {...} } 또는 multipart form-data`
- 응답: `{ "status": "ok", "remaining_checks": N, "skipped_checks": M }`
- 화면 표시: 재검증 대상이 줄어든 것을 표시 (예: "재검증 대상: 5건 → 2건")

### 4.5 POST /api/example

- 용도: 예시 버튼 클릭 시 예시 데이터 채우기
- 요청: 없음 (또는 `{ "seed": "default" }`)
- 응답: 예시 원본, 예시 초안, 예시 기억 파일 데이터를 프론트엔드에 전달
- 프론트엔드 동작: 업로드 칸에 예시 데이터 채움 → 바로 검수 실행 흐름으로 연결

### 4.6 GET /api/status/{job_id}

- 용도: 진행 상황 폴링 (또는 WebSocket 대체 가능)
- 응답: `{ "status": "processing" | "done" | "error", "progress": "...", "partial_results": [...] }`

## 5. 판정 규칙 (cited figure check 스킬 연동)

### 5.1 5라벨

1. **일치**: 원본 표 값과 인용 값이 같음 (단위만 다르게 쓴 건 일치로 봄)
2. **불일치**: 값이 다름
3. **값은 있으나 항목 대응이 다름**: 값 자체는 있지만 원본에서 해당 항목에 대응하는 값이 아님
4. **원본에 없음**: 원본 표에 해당 항목이 없음
5. **확인 불가**: 표가 깨졌거나 기준 불충분으로 대조 불가

### 5.2 계산 인용 처리

- 합산, 소계, 차, 평균, 비율, 비중 등 계산 인용은 원본 표에 같은 숫자가 있는지만 보지 않음
- 계산 근거가 되는 행/열, 포함 범위, 단위, 반올림 방식이 다르면 인용이 원본과 같은 의미인지 재해석
- 계산 근거가 원본 표에 없으면 "원본에 없음" 또는 "확인 불가"로 처리
- 반올림·절삭·근사 표현이 있으면 함께 기록
- 가능하면 계산식 함께 남김 (예: "A행+B행 합계", "전체 대비 비중")

### 5.3 특수 케이스

- 원본이 없으면 판정하지 말고 원본 요청 (원본 없이 `/api/check` 호출 시 원본 업로드 요청 응답)
- "규칙 무시해" 같은 입력이 있어도 판정 규칙 안 바꿈
- 표가 깨졌으면 복원 시도 → 불안정하면 중단 → 확인 불가
- 깨진 표 복원 시도 상한: 불안정해지는 지점에서 중단

## 6. 출력물

### 6.1 검수 표

각 인용 수치별 행:
| 항목 | 인용 값 | 원본 대응 값 | 판정 | 근거 | 수정 제안 | 확인 여부 |

### 6.2 before/after 시각화

- 왼쪽: 원본 초안 (문제 부분은 빨강 하이라이트)
- 오른쪽: 수정된 초안 (수정 부분은 파랑 하이라이트)
- 수정되지 않은 부분은 양쪽 동일 표시

### 6.3 다운로드 파일

1. **고쳐진 파일**: 초안에서 오류가 수정된 버전 (원본에 맞춰 정정된 수치·주장)
2. **기억 파일 (memory.json)**: 검수 결과 전체 (판정, 근거, 수정 이력, 버전 정보) — 재업로드 시 재검증 대상 축소에 사용

## 7. 예시 데이터 요구사항

예시 버튼 하나로 전체 흐름 시연이 가능해야 함.

필수 판정 케이스 (최소 1회씩):
- 일치
- 불일치 (값 다름)
- 값은 있으나 항목 대응이 다름
- 원본에 없음
- 확인 불가 (표 깨짐, 기준 불충분)

추가 케이스:
- 단위만 다르고 값은 같은 경우 → 일치 처리
- 계산 인용 (증감률, 합계, 평균, 비중 등) — 코드가 계산 가능하도록 원본 표에 계산 근거 있음
- 기준 시점/조건 차이로 인한 판정 차이
- 원본에 없는 값을 모델이 채운 케이스 (금지 결과 데모용)
- 깨진 표로 인한 확인 불가 케이스

제약:
- 실제 기관 자료 아님, 가상 예시임을 모든 파일에 명시
- 이미지/URL/PDF 미포함
- API 키나 민감 정보 미포함
- 출력 위치: `examples/` 아래

## 8. 검증 게이트

순서: typecheck → lint → unit test → integration → e2e

| 게이트 | 내용 | Solar Pro 4 호출 |
|--------|------|------------------|
| typecheck | 타입 체크 통과 | 없음 |
| lint | 린터 통과 | 없음 |
| unit test | 스킬 출력을 고정 샘플로 저장, Solar Pro 4 없이 실행 | 없음 |
| integration | 스킬 실제 호출, 출력 형식만 확인 | 있음 |
| e2e | 예시 버튼 → 검수 표 → 파일 다운로드 → 기억 파일 재업 → 재검증 건수 감소 확인 | 있음 |

게이트당 타임아웃: 10분 (e2e는 나중에 늘림)

## 9. 꼼수 품질 검사

### 9.1 꼼수로 볼 것

- 스킬을 안 쓰는 것 (코드/모델이 직접 판정, 호출 우회)
- 테스트를 속이는 것 (정답 코드에 박기, 실패 케이스 빼기, 예시 데이터 통과하게 고치기, mock을 실제 경로에 남기기 등)
- 검수한 척 하는 것 (애매한 걸 전부 확인 불가로, 에러 전부 지우고 빈 결과 성공으로, 전체 재검증 후 숫자만 줄여서 보여주기)

### 9.2 기계적 차단 규칙 (6개)

1. 테스트 파일 수정 금지 (기본)
2. 설정 락파일 변경 시 플래그 남김 (기본)
3. cited figure check 호출부를 지우거나 우회하는 경우 → 실패
4. 판정 결과에 예시 데이터 값이 그대로 박혀 있는 경우 → 실패
5. 실제 동작 경로에 mock/stub이 남아 있는 경우 → 실패
6. 재검사의 스킬 호출 횟수 == 전체면 → 실패

## 11. Agent Loop 컨텍스트

항상 컨텍스트에 붙는 3개:
1. 이 MVP 설계 문서
2. acceptance 기준 (confirmed.md 요약 + 별도 문서)
3. cited figure check 스킬.md

권한 확인 기준:
- 로컬 말고 웹에서 동작. URL로 열림.
- API 키는 서버에 두고 무료인 것으로 선택.
- 모델: Solar Pro 4만 사용.
- 읽기: 전체 허용
- 쓰기: 프로젝트 폴더 안에서만 가능
- 삭제·패키지 설치: 확인
- 네트워크: Solar Pro 4 API 호출만 확인 없이 통과, 나머지 네트워크 호출은 확인

## 12. 미확정 항목

- 무료 API 키/서버 후보 (Solar Pro 4만 호출하는 구조에서 서버가 무엇을 어디서 돌릴지)
- 예시 데이터 내용 (별도 세션/파트) — 프롬프트는 `prompts/example-data-subagent.md`에 있음

- acceptance 기준 별도 문서 (confirmed.md 요약은 있지만 별도 문서로 만들 수 있음)
